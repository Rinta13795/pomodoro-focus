一、实验目的

掌握使用企业管理器和 SQL 语句创建、修改、删除索引的方法，理解聚簇索引、非聚簇索引和唯一索引的特点，并认识索引对数据库查询性能的影响。

二、实验环境

使用 SQL Server 数据库管理系统，在 jxsk 教学数据库上进行索引创建与删除操作。

三、实验内容与过程

1. 用企业管理器为表 TEST_SC 创建 PRIMARY KEY。

操作步骤：在企业管理器中打开表 TEST_SC 的设计视图，选中 SNO 和 CNO 两列，右键选择“设置主键”，系统自动创建主键索引。

执行结果：成功创建主键 PK_TEST_SC，该主键索引为聚簇索引，索引列为 SNO 和 CNO。

2. 用 SQL 为表 T 在 TNO 列上按降序创建聚簇索引 IND_TNO。

USE jxsk
CREATE CLUSTERED INDEX IND_TNO ON T(TNO DESC)
GO

执行结果：成功创建聚簇索引 IND_TNO，表 T 的记录逻辑上按照 TNO 降序排列。

3. 用企业管理器为表 T 创建非聚簇索引 IND_SN_AGE。

操作步骤：右键表 T，选择“所有任务”中的“管理索引”，点击“新建”，输入索引名 IND_SN_AGE，选择列 SN 升序、AGE 降序，并设置为非聚簇索引。

执行结果：成功创建非聚簇索引 IND_SN_AGE，可提高按姓名和年龄组合检索时的查询效率。

4. 用 SQL 为表 C 在 CN 列上按升序创建唯一索引 IND_CN。

USE jxsk
CREATE UNIQUE INDEX IND_CN ON C(CN)
GO

执行结果：成功创建唯一索引 IND_CN，保证课程名 CN 列中不允许出现重复值。

5. 用企业管理器删除表 C 中的索引 IND_CN。

操作步骤：右键表 C，进入“管理索引”，在索引列表中选中 IND_CN，点击“删除”后确认。

执行结果：成功删除唯一索引 IND_CN。

6. 用 SQL 删除表 T 中的索引 IND_SN_AGE。

USE jxsk
DROP INDEX T.IND_SN_AGE
GO

执行结果：成功删除表 T 上的非聚簇索引 IND_SN_AGE。

四、思考题

1. 一个表只能有 1 个聚簇索引，因为聚簇索引决定数据的物理存储顺序；一个表可以有多个非聚簇索引。在 SQL Server 2000 中，非聚簇索引最多可建立 249 个。

2. 主索引和唯一索引的区别在于：主索引通常与主键约束对应，不允许 NULL，一个表只能有一个主键；唯一索引用于保证列值唯一，但一个表可以创建多个唯一索引，并且允许存在空值。

3. 当一个表尚未创建聚簇索引时再创建主键，系统通常会自动在主键列上创建聚簇索引。因此主键不仅起到唯一性和非空约束的作用，还会提高基于主键检索的效率。

五、实验总结

通过本次索引实验，我对数据库中索引的作用和类型有了更加清晰的认识。实验中分别完成了主键索引、聚簇索引、非聚簇索引和唯一索引的创建与删除操作，使我掌握了企业管理器和 SQL 两种不同方式下的索引管理方法。

在实践过程中，我认识到索引能够显著提高查询效率，尤其适用于频繁检索和排序的字段；但同时索引也会增加存储空间占用和数据维护成本。因此在实际数据库设计中，应根据业务需求合理创建索引，避免盲目增加索引而影响整体性能。本实验加深了我对数据库物理设计和性能优化的理解。
